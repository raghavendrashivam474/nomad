### 3.2 `packages/nomad_core` — Pure Dart Domain Library

**Purpose:** Platform-agnostic domain primitives that will be consumed by all future Nomad applications (mobile, desktop, web).

**Contents:**

| File | Responsibility |
|---|---|
| `nomad_exception.dart` | Base `NomadException` hierarchy: `DomainException`, `ContractViolationException`. All carry `message`, optional `code`, and optional `cause`. |
| `unique_id.dart` | `EntityId` value object with equality semantics and empty-string assertion guard. |
| `nomad_core.dart` | Barrel export file. |

**Key design decisions:**
- Zero Flutter dependencies. The `pubspec.yaml` declares only `sdk: '>=3.0.0 <4.0.0'` with no Flutter SDK reference.
- Exception hierarchy is prepared for future contract governance (e.g., `ContractViolationException` will be thrown when capability contracts are breached).
- `EntityId` uses `const` constructors and value equality, ready for use in S0.0.2's Project model.

**Tests:** 4 unit tests covering equality, hashing, toString formatting, and assertion guards. All passing.

### 3.3 `apps/nomad_mobile` — Flutter Application

**Purpose:** The primary Nomad client application targeting Android (phone + tablet).

**Entry flow:**
```
main.dart → NomadApp (MaterialApp with M3 theming) → AppShell (LayoutBuilder)
```

**Responsive shell implementation:**

| Screen Width | Layout | Key Elements |
|---|---|---|
| < 600dp (Phone) | Compact centered column | Terminal icon, "Nomad" title, tagline, "Get Started" button |
| ≥ 600dp (Tablet) | NavigationRail + expanded content | Sidebar with "Lab" and "Projects" destinations, centered hero content |

**Key design decisions:**
- `LayoutBuilder` was chosen over `MediaQuery` for the responsive breakpoint because it responds to the actual available layout constraints rather than the full screen dimensions. This will matter when Nomad runs in split-screen or multi-window modes on tablets.
- Material 3 theming with `ColorScheme.fromSeed` for both light and dark modes, following system preference (`ThemeMode.system`).
- The tablet `NavigationRail` is a structural placeholder — its destinations will be populated with real capabilities in S0.0.4+.
- No state management library was introduced. The shell is entirely stateless, which is correct for S0.0.1's scope.

**Tests:** 2 widget tests simulating phone (390×844) and tablet (1024×768) viewports. Both verify correct layout rendering. All passing.

## 5. Problems Encountered & Mitigations

### Problem 1: `flutter --version` Hung on First Invocation

**Symptom:** The initial `flutter --version` command during pre-implementation inspection appeared to hang indefinitely with no output.

**Root Cause:** Flutter's first-run telemetry/analytics prompt and/or Dart SDK initialization on a cold start. The command was waiting for interactive input or performing background SDK validation.

**Mitigation:**
- Interrupted with `Ctrl+C`.
- Subsequent invocations used `--suppress-analytics` flag.
- After the first warm-up, all Flutter commands executed normally.
- **Recommendation for CI:** Ensure `flutter config --no-analytics` is set in the CI runner environment.

### Problem 2: Non-Git Parent Workspace with 25+ Sibling Projects

**Symptom:** The workspace root (`Anti-grav`) was not a Git repository and contained many unrelated project directories. Initializing Git at the root would have entangled Nomad's history with unrelated work.

**Root Cause:** The developer's workspace is a multi-project monodirectory, not a monorepo.

**Mitigation:**
- Created a dedicated `nomad/` subdirectory.
- Initialized Git exclusively within `nomad/`.
- This preserves complete isolation from sibling projects.
- **Trade-off:** Nomad is nested one level deeper than a standalone clone would be. If Nomad later becomes a standalone repository, it can be extracted cleanly since its `.git/` is self-contained.

### Problem 3: Dependency Version Gaps

**Symptom:** After `flutter pub get`, several packages reported newer available versions incompatible with current constraints:
- `flutter_lints 3.0.2` (6.0.0 available)
- `lints 3.0.0` (6.1.0 available)
- `clock`, `matcher`, `meta`, `stack_trace`, `test_api`, `vector_math`, `material_color_utilities`

**Root Cause:** The `pubspec.yaml` files specify conservative version constraints (`flutter_lints: ^3.0.0`, `lints: ^3.0.0`) and the Flutter 3.44.2 SDK pins certain transitive dependency versions.

**Mitigation:**
- Accepted current versions as stable and compatible.
- Did not force-upgrade to avoid introducing breaking changes during a foundation sprint.
- **Recommendation for S0.0.2+:** Run `flutter pub outdated` and evaluate upgrades when new capabilities are introduced.

### Problem 4: `flutter create` Generated Boilerplate Overwritten

**Symptom:** `flutter create` generated a default `pubspec.yaml` (with `cupertino_icons` dependency) and default `lib/main.dart` / `test/widget_test.dart`.

**Root Cause:** Standard Flutter scaffolding behavior.

**Mitigation:**
- Immediately overwrote `pubspec.yaml` with the Nomad-specific configuration (adding `nomad_core` path dependency, removing `cupertino_icons`).
- Replaced `lib/main.dart` with the clean `NomadApp` entry point.
- Replaced `test/widget_test.dart` with responsive phone/tablet widget tests.
- `flutter pub get` confirmed the dependency swap cleanly (`cupertino_icons` removed, `nomad_core` added).

### Problem 5: Code Formatting Drift After Manual File Creation

**Symptom:** After writing Dart files via PowerShell `Set-Content`, `dart format .` reported 8 files changed (4 in each package).

**Root Cause:** PowerShell heredoc strings (`@'...'@`) do not enforce Dart formatting conventions (trailing commas, line length, indentation).

**Mitigation:**
- Ran `dart format .` in both packages as the final step before commit.
- **Recommendation:** Configure IDE auto-format-on-save and consider adding a pre-commit hook running `dart format --set-exit-if-changed .` in future sprints.

## 9. Recommendations for S0.0.2

1. **Project Domain Model:** Introduce `Project` entity in `nomad_core` with `id` (using `EntityId`), `name`, `type`, `createdAt`, `updatedAt`. This will be the first real capability contract.
2. **Dependency Audit:** Evaluate upgrading `lints` to 6.x and `flutter_lints` to 6.x after confirming compatibility with Flutter 3.44.2.
3. **Pre-commit Hooks:** Consider adding `dart format --set-exit-if-changed` and `dart analyze --fatal-infos` as Git pre-commit hooks to prevent formatting drift.
4. **CI Analytics Suppression:** Add `flutter config --no-analytics` to the CI workflow to prevent the first-run hang we encountered locally.
